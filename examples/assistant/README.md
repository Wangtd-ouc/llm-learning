# 综合示例（RAG + Agent）

把前面两个示例合并成一个系统：模型在 ReAct 循环里自己决定用哪个工具。

## 能力

| 工具 | 类型 | 说明 |
|---|---|---|
| `search_knowledge(问题)` | RAG | 检索本地知识库，返回带出处的资料 |
| `calc(表达式)` | 工具 | 安全四则运算 |
| `get_stock_price(代码)` | 工具 | 示例股票价格（模拟数据） |
| `get_current_time()` | 工具 | 当前时间 |

## 运行

```bash
python3 examples/assistant/assistant.py
```

脚本内置四个演示问题，分别覆盖：知识问答（RAG）、单步计算、多步组合（查价+算钱）、时间工具。

## 代码结构

- `TOOLS`：工具注册表；`tool_search_knowledge` 复用了 `rag_demo.py` 的索引与检索；
- `SYSTEM_PROMPT`：告诉模型有哪些工具、输出格式、以及“用了知识库必须列出来源”；
- `run_question()`：ReAct 主循环（与 `agent_demo.py` 相同思路）。

## 与前面示例的关系

- RAG 示例教的是“检索 + 生成”；
- Agent 示例教的是“工具调用循环”；
- 本示例把“检索”本身变成一个工具，模型可以按需调用——这就是生产系统里最常见的组合方式。

## 验证记录（2026-08-28）

- 环境：Ollama 0.32.14 + qwen3.5:4b；
- “LoRA 主要微调的是什么参数？”→ 调用 RAG 工具，回答并列出 `lora-finetune.md`、`llm-transformer.md`；
- “23×17 等于多少？”→ 调用计算器 → 391；
- “查 600519 价格，买 10 手多少钱？”→ 查价 → 计算 → 1,500,000 元；
- “现在几点？”→ 调用时间工具 → 返回真实时间。

## 常见坑（本示例真实踩过）

1. 无参数工具（`get_current_time()`）会被解析成传了一个空字符串，需要单独处理；
2. 模型常在同一轮里“先写行动、又提前写回答”，必须优先执行行动，否则会漏掉工具；
3. 模型可能误说自己“无法访问设备”，其实只是没按格式调用工具——提示词要把格式写死。

## 接入微调模型（进阶实验）

```bash
# 1. 先启动微调模型的 OpenAI 兼容服务（见 examples/finetune/README.md）
# 2. 让综合示例调用它
python3 examples/assistant/assistant.py \
  --api openai --base-url http://127.0.0.1:8081 \
  --model merged_model --question "LoRA 主要微调的是什么参数？"
```

实测（2026-08-28）：用只微调过“公司介绍”的 0.5B 模型跑 Agent 循环，模型只会重复训练过的格式，不会调用工具。这说明微调会窄化模型行为；要让微调模型当 Agent，训练数据里必须包含工具调用格式样本。详细解读见 `docs/05-综合项目.md`。
