# Agent：让模型学会使用工具

> 目标：理解 Agent 的基本结构（模型 + 工具 + 循环），并读懂 `agent_demo.py` 的 ReAct 循环。

## 1. 什么是 Agent

单独的 LLM 只能“说”，不能“做”：它不会查数据库、不会算准大数、不会访问网页。Agent（智能体）就是给模型装上“手和脚”：

**Agent = 大模型（决策大脑）+ 工具（执行能力）+ 循环（思考-行动-观察）**

## 2. 核心模式：ReAct

ReAct（Reasoning + Acting）是目前最基础的 Agent 模式，流程是：

1. 模型看到任务，输出“思考：我该怎么做”；
2. 模型输出“行动：调用某个工具（参数）”；
3. 程序执行工具，把结果返回给模型；
4. 模型基于结果继续思考，直到输出最终回答。

项目示例 `agent_demo.py` 里，模型先输出：

```text
思考: 首先需要查询股票 600519 的当前价格...
行动: get_stock_price(600519)
```

程序解析出工具名和参数，执行后把结果放回对话：

```text
工具结果：贵州茅台（600519）现价 1500.0 元
```

模型接着输出 `行动: calc(1500 * 10 * 100)`，最终给出 `回答: 1500000 元`。

这个“循环”本身不复杂，难点在于：**让模型稳定地输出可解析的指令**，以及**设计好工具**。

## 3. 两种工具调用方式

### 方式 A：文本协议（示例采用）

模型输出固定格式的文本，例如 `行动: calc("23*17")`，程序用正则解析。优点：任何模型都能用；缺点：模型可能格式飘。

### 方式 B：原生函数调用（Function Calling）

模型训练时就支持“结构化输出工具调用”，例如 OpenAI、Claude 的 `tools` 参数，Ollama 对 qwen3 系列也支持。模型直接返回 JSON 结构（如 `{"name": "calc", "arguments": {"expression": "23*17"}}`），程序不用猜格式。

生产项目优先用方式 B，它更稳定；方式 A 适合教学和理解原理。本项目两个版本都实现了：`agent_demo.py`（方式 A，文本协议）、`agent_tools_demo.py`（方式 B，原生函数调用）。

## 4. Agent 的四个进阶能力

### 记忆（Memory）

- 短期记忆：把对话历史放进上下文，示例就是这么做的；
- 长期记忆：把重要信息存到文件/向量库，下次会话读取。

### 规划（Planning）

复杂任务先拆成子任务。例如“调研竞品并写报告”可以拆成：搜资料 → 汇总 → 写报告 → 校对。进阶框架（如 LangGraph）支持显式的任务图和状态机。

### 多智能体协作

多个 Agent 各司其职（一个查资料、一个写代码、一个审核），通过消息协作。适合复杂流水线，但会带来协调和成本问题，新手先别急着上。

### 工具生态

工具可以是代码函数、API 调用、数据库查询、浏览器操作。关键是给每个工具写清楚“名称、参数、用途”，模型才知道什么时候用。

## 5. 主流框架

- **LangChain / LangGraph**：生态最大，抽象多，适合复杂工作流；
- **OpenAI Agents SDK / Claude Agent SDK**：官方出品，简单直接；
- **Ollama 原生 tools**：本机即可体验函数调用，无云端依赖；
- **Dify / Coze**：低代码平台，适合快速搭应用。

学习建议：先用本项目的手写循环理解原理，再去看框架，你会发现框架只是把“循环、解析、记忆、工具注册”封装好了。

## 6. Agent 的风险与安全

- **工具权限**：给模型的工具要最小权限，别让它能删除文件、转账；
- **提示注入**：模型读取的外部内容（网页、邮件）可能藏指令，诱导它做危险操作；
- **循环失控**：要设置最大步数和超时，防止无限循环；
- **结果不可信**：工具结果也要校验，模型可能“想当然”跳过工具直接编答案。

## 7. 动手练习

1. 运行 `python3 examples/agent/agent_demo.py`，观察两步工具调用的日志。
2. 给 `MOCK_STOCKS` 增加一只股票，问一个需要查询后计算的问题。
3. 修改 `SYSTEM_PROMPT`，故意把格式说明写模糊，观察模型如何“跑偏”——体会提示词对 Agent 的重要性。
4. 进阶：给 Agent 加一个 `get_current_time` 工具（用 `datetime`），问“现在是几点”。

## 8. Agent 自动化评估（本项目已实现）

生产里改任何一环（提示词、工具、模型）都应该重跑回归测试。`examples/agent/evaluate_agent.py` 内置 5 个测试用例，每个用例检查两个维度：

- **工具选择**：预期工具是否都被调用（该检索时检索、该计算时计算）；
- **答案正确**：最终回答是否包含预期关键词。

实测结果（2026-08-28，qwen3.5:4b）：**5/5 全部通过**，报告见 `examples/agent/reports/agent_eval_report.md`。

这份评估脚本本身就是“Agent 构建”的一部分：一个没有测试的 Agent 系统，改一个提示词就可能悄悄变坏，而你毫无察觉。
