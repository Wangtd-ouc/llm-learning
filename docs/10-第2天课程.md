# 第 2 天课程：Agent + 微调（含答案）

> 配套阅读：`docs/03-Agent.md`、`docs/04-微调.md`。上午 Agent，下午微调，各约 45 分钟。

## 一、Agent：给模型装上“手和脚”

单独的模型只会“说”，不会“做”。Agent 就是给它加上执行能力：

**Agent = 大模型（决策） + 工具（执行） + 循环（思考-行动-观察）**

核心模式叫 **ReAct**：

```text
思考 → 行动（调用工具） → 观察（工具结果） → 再思考 → …… → 回答
```

## 二、两种工具调用方式

1. **文本协议**（`agent_demo.py`）：模型输出“行动: calc(23*17)”，程序用正则解析。
   优点：任何模型都能用；缺点：模型格式一飘就解析失败。
2. **原生函数调用**（`agent_tools_demo.py`）：工具用 JSON Schema 声明，模型直接返回结构化的 `tool_calls`。
   **生产推荐用这种**，稳定、不用猜格式。

进阶概念（先知道存在）：短期/长期记忆、任务规划、多智能体协作。安全红线：**给模型的工具要最小权限**，防止它误删文件或执行危险操作。

## 三、微调：什么时候用

先想清楚需求：

- 想让模型“知道一件事”→ **RAG**（补知识）；
- 想让模型“习惯一种格式/风格”→ **微调**（学行为）；
- 临时规则 → **改提示词**。

微调 = 用“输入 → 期望输出”的数据继续训练模型，让它模仿你的数据。

## 四、LoRA / QLoRA 为什么便宜

- **LoRA**：冻结原模型权重，在旁边插入两个小矩阵，只训练它们（约占 0.1%～1% 参数）；
- **QLoRA**：再把原模型量化到 4-bit 加载，显存需求进一步下降；
- 本项目实测：0.5B 模型只训练 0.297% 参数，显存峰值 1.23GB，16GB 内存的 Mac 毫无压力。

## 五、微调的标准流程

**定义目标 → 准备数据（JSONL）→ 选基座 → 训练 → 评估 → 部署**

数据格式示例：

```json
{"instruction": "把句子翻译成英文", "input": "今天天气很好", "output": "The weather is nice today."}
```

数据质量 > 数量：几百条高质量数据，常好过几万条脏数据。训练集和测试集必须分开。

## 七、检查点答案（先自己答再看）

1. Agent 的三个组成部分是什么？
   **答：模型 + 工具 + 循环**。
2. ReAct 循环的正确顺序？
   **答：思考 → 行动 → 观察 → 继续思考 → 回答**。
3. 文本协议和原生函数调用，生产优先用哪个？
   **答：原生函数调用**（结构化、稳定，不用解析文本格式）。
4. 想让模型“记住新事实”，优先用 RAG 还是微调？
   **答：RAG**。微调记新事实容易幻觉且成本高。
5. LoRA 为什么省资源？
   **答：冻结原模型，只训练插入的低秩矩阵（约 0.1%～1% 参数）**。
6. 微调后只看训练集损失下降，够吗？
   **答：不够**。必须用测试集和实际输出评估，警惕过拟合与灾难性遗忘。
