# 第 1 天课程：LLM 核心框架 + RAG（含答案）

> 配套阅读：`docs/01-llm基础框架.md`、`docs/02-RAG.md`。本文件是课程 + 检查点，可以离线按自己的节奏完成。

## 一、LLM 是什么：一台“猜下一个词”的机器

大模型做的事情用一句话说：**根据前面已出现的文字，预测下一个最可能出现的词，然后重复几千次**。

类比输入法联想：你打“今天天”，它猜“气”。大模型只是规模大了几十亿倍、学的文本多了几个数量级，于是“猜”出来的东西看起来像真在思考和写作。

关键单位是 **token（词元）**：

- 英文常见单词约 1 个 token；
- 中文一个汉字约 1～2 个 token；
- “上下文窗口 4096”= 4096 个 token，约等于 2000～3000 个汉字。

## 二、底层架构：记住三句话

1. **自注意力**：生成时给前面的每个词算“谁更重要”，决定重点参考谁；
2. **位置编码**：补上词的先后顺序信息；
3. **因果掩码**：生成时只能看“过去”，不能偷看“未来”。

不需要记公式，能解释“自注意力是核心”即可。

## 三、三阶段生命周期

| 阶段 | 做什么 | 类比 |
|---|---|---|
| 预训练 | 海量文本上学习“猜下一个词” | 读了很多书 |
| 指令微调（SFT） | 用“问题→答案”数据学会按指令答题 | 培训班学答题格式 |
| 对齐 | 让回答更有用、更安全 | 学什么话该说 |

你平时用的模型是三个阶段完成后的成品。**微调只是中间一个环节**。

## 四、你日常能控制的参数

- **system prompt**：给模型立的规矩，优先级最高；
- **temperature**：0 接近确定，0.7 以上更发散（RAG 示例用 0.2，Agent 用 0.0）；
- **max_tokens**：最多生成多少 token。

## 五、模型的五个“不会”

1. 会**幻觉**（编造事实）；
2. 知识**过时**；
3. **上下文有限**；
4. 不会**真计算**；
5. 不知道**你的私有文档**。

对应关系：RAG 补知识、Agent 补能力、微调改格式。

## 六、RAG 五环节

**切块 → 向量化 → 检索 → 重排（可选）→ 生成**

两种检索的区别（本项目实测）：

- TF-IDF：靠关键词重合，命中可能带出多个文件；
- 向量检索：靠语义相似度，命中更聚焦；
- 两者最终都由模型“基于资料回答并带出处”。

生产环境 = 嵌入模型 + 向量数据库（Milvus / Chroma / pgvector）。

## 八、检查点答案（先答后看）

1. “上下文窗口 4096”的单位是什么？
   **答：token**。不是汉字、不是句子。中文一个汉字约 1～2 个 token。
2. temperature 调高，输出会怎么变？
   **答：更随机/更发散**。同样的输入可能得到更多样的回答，也可能更不靠谱；调低则更稳定、更确定。
3. RAG 主要解决了模型的哪个“不会”？
   **答：不知道你的私有文档/知识过时**（对应“边界”第 2、5 条）。它让模型基于检索到的资料答题，而不是凭记忆编。
