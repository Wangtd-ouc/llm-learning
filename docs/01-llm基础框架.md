# LLM 基础知识框架

> 目标：读完这一篇，你能向别人解释清楚“大语言模型是什么、怎么工作、能做什么、不能做什么”。

## 1. LLM 是什么

大语言模型（Large Language Model，LLM）是一种基于深度学习的文本模型。它做的事情可以概括成一句话：

**根据前面已经出现的文字，预测下一个最可能出现的词（token）。**

把这个过程重复几千次，就得到了我们看到的“生成文章、写代码、回答问题”。ChatGPT、Qwen、DeepSeek 等产品，本质都是这个“猜下一个词”的模型，加上外围的产品工程。

## 2. 第一个关键概念：Token（词元）

模型不是按“字”或“词”处理文本，而是按 token 处理。token 是模型自己的“语言单位”：

- 英文里一个常见单词通常是一个 token，例如 `hello`；
- 中文里一个汉字通常对应 1～2 个 token；
- 生僻词或长单词可能被切成多个 token。

所以“上下文窗口 4096”指的是 4096 个 token，而不是 4096 个汉字。这直接影响成本和效果，也是后面 RAG 要解决的核心约束之一。

## 3. 底层的 Transformer 架构

现代 LLM 几乎都基于 Transformer（2017 年提出）。你只需要理解四个要点：

1. **自注意力（Self-Attention）**：生成下一个词时，模型会给前面的每个词算一个“重要程度”，决定重点参考谁。这是模型能理解长句关系的核心。
2. **位置编码**：模型本身不知道词的先后顺序，需要额外注入位置信息（现代主流是 RoPE 旋转位置编码）。
3. **因果掩码**：生成时必须“只看过去、不看未来”，保证自回归生成。
4. **堆叠层数**：把很多层 Transformer 堆起来，层数越多、参数越多，模型容量越大。

## 4. 模型的“三阶段”生命周期

一个能用的对话模型，通常经历三个阶段：

| 阶段 | 做什么 | 类比 |
|---|---|---|
| 预训练（Pre-training） | 在海量公开文本上学习“预测下一个词”，获得语言能力和世界知识 | 读书读到海量知识 |
| 指令微调（SFT） | 用“指令 → 回答”的数据，教会模型听话、按格式回答 | 上培训班学“怎么答题” |
| 对齐（Alignment） | 用人类偏好让回答更有用、更安全（RLHF、DPO 等） | 学“什么话该说、怎么说” |

你平时用的模型是三个阶段都完成后的成品。**微调（SFT）只是中间一个环节**，理解这一点很重要。

## 5. 使用 LLM 时的关键参数

调用模型时，你控制的主要参数：

- **system prompt**：给模型的“角色设定和规则”，优先级高于用户消息；
- **temperature**：随机性。0～1 之间，0 接近确定性输出，0.7 以上更发散；
- **top_p**：只从累计概率前 p 的候选中采样，另一种控制随机性的方式；
- **max_tokens / num_predict**：最多生成多少 token；
- **上下文窗口**：输入 + 输出能容纳的总 token 数。

示例里我们用 `temperature=0.2` 让 RAG 回答更稳定，用 `temperature=0.0` 让 Agent 严格走工具流程。

## 6. 模型的已知边界（必须知道）

- **幻觉（Hallucination）**：模型会一本正经地编造不存在的事实，因为它本质上在“猜概率”，不是在查数据库。
- **知识过时**：训练数据有截止时间，之后发生的事它不知道。
- **上下文有限**：超过窗口的内容会被截断，模型“记不住”整本书。
- **不会真正计算**：复杂计算容易出错，应该让它调用工具（这正是 Agent 示例做的事）。
- **不会真正检索**：它不知道你硬盘里的私有文档，除非你用 RAG 把内容喂给它。

这三条边界，正好对应你学习路线里的三大技能：RAG（补知识）、Agent（补能力）、微调（改风格与格式）。

## 7. 关键术语速查

| 术语 | 一句话解释 |
|---|---|
| Token | 模型处理文本的最小单位 |
| Transformer | 现代 LLM 的基础网络结构 |
| 自注意力 | 计算词与词之间关联度的机制 |
| 预训练 | 在海量文本上学习语言规律 |
| SFT（监督微调） | 用指令-回答数据让模型听话 |
| RLHF / DPO | 让模型对齐人类偏好的训练方法 |
| 上下文窗口 | 一次能处理的 token 上限 |
| 温度（temperature） | 控制输出随机性 |
| 幻觉 | 模型编造看似合理的内容 |
| Embedding（嵌入） | 把文本转成向量，语义相近则距离近 |
| Prompt | 你给模型的输入文本 |
| 推理（Inference） | 用训练好的模型生成输出，即日常使用 |

## 8. 动手练习

1. 运行项目里的任何示例前，先看一遍 `examples/common/ollama_client.py`，理解一条消息是怎样发给模型的。
2. 用 `ollama` 命令试试 temperature 0 和 1.5 的差异（例如让模型讲笑话）。
3. 用中文统计“一句话里有多少 token”，建立 token 的直觉（Ollama 的 `/api/chat` 响应里有 `eval_count` 字段）。
