# RAG：检索增强生成

> 目标：理解 RAG 为什么存在、标准流程是什么，并会用项目里的 `rag_demo.py` 亲手搭一个问答机器人。

## 1. 要解决的问题

模型的知识在训练时就被“冻结”了。当你想让它回答以下问题时，直接问效果很差：

- “我们公司最新的产品规格是什么？”（私有数据，模型没见过）
- “昨天发布的新政策是什么？”（知识过时）
- “这份 200 页报告里写了什么结论？”（太长，塞不进上下文）

RAG 的思路：**别让模型凭记忆回答，先把相关资料找出来，和问题一起交给它。**

## 2. 标准流程（五步）

### 第 1 步：文档切块（Chunking）

把长文档切成小块，例如按标题、段落或固定长度（256～512 token）切。切块时要保留来源信息，方便回答时标注出处。

切块大小的权衡：

- 切得小 → 检索更精准，但可能缺少上下文；
- 切得大 → 上下文完整，但混入无关内容，还可能超出窗口。

项目示例采用“标题 + 段落”合并成块，就是最简单的实用策略。

### 第 2 步：向量化（Embedding）

把每个文本块转换成向量（几百到几千维的数字列表）。**语义相近的文本，向量距离也近**，这是检索的基础。

生产环境用专门的嵌入模型（如 `nomic-embed-text`、`bge-m3`）和向量数据库（如 Milvus、Chroma、pgvector）。示例为了零依赖，用 TF-IDF 代替向量，原理骨架完全相同。

### 第 3 步：检索（Retrieval）

把用户问题也转成向量，和知识库所有文本块算相似度（通常用余弦相似度），取最相似的 Top-K 个。

进阶做法是混合检索：向量检索（懂语义）+ 关键词检索（精确匹配专有名词），再合并结果。

### 第 4 步：重排（Rerank，可选）

向量检索的前 K 个候选可能顺序不准。可以用一个更精细的排序模型对候选重新打分，通常能把准确率提升一截。小项目可以跳过。

### 第 5 步：生成（Generation）

把“指令 + 检索到的文本块 + 用户问题”拼成一个提示词，要求模型：

- 只依据资料回答，不编造；
- 资料不足时说“不知道”；
- 标注引用来源。

这一步完全不需要改模型，所以 RAG 是“轻量、可快速上线”的方案。

## 3. 项目示例对照

`examples/rag/rag_demo.py` 与标准流程的对应关系：

| 标准流程 | 示例里的实现 |
|---|---|
| 切块 | `load_chunks()`：按标题 + 段落切，保留文件名 |
| 向量化 | `build_index()`：TF-IDF 词频向量 |
| 检索 | `retrieve()`：余弦相似度取 Top-3 |
| 重排 | 省略（教学示例） |
| 生成 | 把资料拼进提示词，调 Ollama 生成 |

## 4. 如何评估 RAG 系统

四个常用指标：

- **检索命中率（Recall）**：正确答案所在的文本块，是否被检索到？
- **检索精确率（Precision）**：检索出来的文本块，有多少是真正相关的？
- **回答忠实度（Faithfulness）**：回答里的内容，是否都来自资料？（防幻觉）
- **回答相关性（Answer Relevance）**：回答是否切题？

实操做法：准备 20～50 道“问题 → 正确答案所在文档”的测试题，跑一遍系统，统计命中率和人工抽检回答质量。

本项目已实现可复现的评估脚本：`examples/rag/evaluate_rag.py`，内置 10 道测试题，输出 TF-IDF 与向量检索的 Recall@1/3/5 对比。真实结果（2026-08-28，小知识库 22 个文本块）：

| 指标 | TF-IDF | 向量检索 |
|---|---|---|
| Recall@1 | 100% | 80% |
| Recall@3 | 100% | 90% |
| Recall@5 | 100% | 100% |

这个结果本身就是一个重要知识点：**检索不是越“高级”越好**。在小知识库、问题与文档关键词重合度高的场景，简单精确的 TF-IDF 可能更强；向量检索的优势体现在大规模知识库和“语义相近但用词不同”的问题上。所以选型必须用评估数据说话，而不是凭感觉。

## 5. 常见问题与对策

| 症状 | 原因 | 对策 |
|---|---|---|
| 检索不到答案 | 切块太碎/太大、关键词不匹配 | 调切块策略、加关键词混合检索 |
| 回答不忠实 | 模型没“只看资料” | 强化提示词、降 temperature、加“资料不足就说不知道” |
| 引用错误 | 检索到的块本身不相关 | 提高检索质量，或加重排 |
| 知识更新慢 | 索引没有增量更新 | 文档变更时重建对应块索引 |

## 6. 动手练习

1. 运行：`python3 examples/rag/rag_demo.py "RAG 的五个环节是什么？"`
2. 在 `knowledge_base/` 里新增一篇你自己的文档（例如“我的工作笔记.md”），问一个只有它能回答的问题，观察检索和回答是否生效。
3. 把 `--top-k` 从 3 改成 1 或 5，比较回答质量变化。
4. 进阶：运行 `python3 examples/rag/rag_embed_demo.py`（向量检索版，已实现），与 TF-IDF 版对比检索命中差别。
