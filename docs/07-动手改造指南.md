# 动手改造指南：给综合示例加一个工具

> 这是“完成清单”里最后一项的标准做法。下面用“新增汇率查询工具”作为完整示范，你照着做就能给这个示例加任何工具。

## 完整流程（5 步）

### 第 1 步：写工具函数

在 `examples/assistant/assistant.py` 的“工具定义”区域加一个普通 Python 函数，返回字符串（模型能看到的就是这个字符串）：

```python
MOCK_RATES = {"USD/CNY": 7.2, "HKD/CNY": 0.92}

def tool_get_exchange_rate(pair: str) -> str:
    """查询示例汇率（模拟数据，非实时行情）。"""
    rate = MOCK_RATES.get(pair.upper())
    if rate is None:
        return f"未找到汇率：{pair}"
    return f"{pair.upper()} 汇率为 {rate}（模拟数据）"
```

要点：**输入参数要简单**（字符串即可），**返回要给模型可用的完整信息**（包括单位、说明），这样模型才不会猜。

### 第 2 步：注册进工具表

同一个文件里有两处要改：

```python
TOOLS = {
    ...
    "get_exchange_rate": tool_get_exchange_rate,   # ① 注册函数
}

TOOL_DESC = "\n".join([
    ...
    "- get_exchange_rate(货币对)：查询示例汇率，例如 get_exchange_rate(\"USD/CNY\")",  # ② 告诉模型怎么用
])
```

### 第 3 步：加一个演示问题（可选）

在 `__main__` 的 `questions` 列表里加一行，跑 `assistant.py` 就能看到新工具被调用。

### 第 4 步：加评估用例（必须）

在 `examples/agent/evaluate_agent.py` 的 `CASES` 里加一条，写清楚“预期调用哪些工具 + 答案应包含什么关键词”：

```python
{
    "question": "查询美元兑人民币汇率，然后计算 100 美元等于多少人民币？",
    "expect_tools": ["get_exchange_rate", "calc"],
    "expect_keywords": ["720"],
},
```

### 第 5 步：跑验收

```bash
python3 examples/agent/evaluate_agent.py
```

新用例必须 PASS；顺手再跑一遍 `python3 examples/practice/verify_all.py` 确认整个系统没被改坏。

## 本次改造的实测记录（2026-08-28）

- 评估用例从 5 个增加到 6 个，全部 PASS（6/6）；
- 汇率问题实测：模型先调 `get_exchange_rate(USD/CNY)` 得到 7.2，再调 `calc(100 * 7.2)` → 720；
- 真实观察：模型在拿到工具结果前，曾在“思考”里猜汇率 7.23，但系统只执行第一个行动、并让工具结果纠正它，最终答案正确——这正是“Agent 必须用工具结果说话”的现场演示。

## 加“知识文档”也一样

想给 RAG 加知识，不用改代码：

1. 把文档放进 `examples/rag/knowledge_base/`（支持 Markdown）；
2. 跑 `python3 examples/rag/rag_embed_demo.py "你的问题"` 验证能检索到；
3. 再向综合示例提一次问，确认它会自动调 `search_knowledge`。

## 常见失败与排查

| 现象 | 原因 | 排查 |
|---|---|---|
| 模型不调用新工具 | 没在 `TOOL_DESC` 里写清楚 | 检查提示词里工具描述 |
| 模型调用但参数错 | 参数格式太复杂 | 简化参数，全用字符串 |
| 工具执行报错 | 函数签名与解析不匹配 | 看日志里的“工具执行出错” |
| 用例 FAIL | 预期关键词和实际输出不一致 | 先手动跑一次问题，看真实答案再校准用例 |
