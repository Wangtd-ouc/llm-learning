# 微调（Fine-tuning）

> 目标：理解微调是什么、什么时候该用、LoRA 为什么省资源，并会跑通一个最小微调实验。

## 1. 先回答：什么时候该微调？

面对“模型表现不好”，先按成本从低到高尝试：

| 方案 | 成本 | 适用场景 |
|---|---|---|
| 改提示词（Prompt） | 最低 | 格式、语气、少量规则 |
| RAG | 低 | 模型缺知识、知识会更新 |
| 微调（SFT） | 高 | 让模型学会固定的输出格式/风格/领域术语，且 RAG 不够用 |
| 全量重训 | 最高 | 极少情况，一般用不上 |

记住一个经验：**微调是“学行为”，RAG 是“补知识”**。想让模型“知道一件事”，先试 RAG；想让模型“习惯一种答题方式”，才考虑微调。

## 2. 微调在做什么

微调 = 用“输入 → 期望输出”的数据，继续训练模型，让模型学会模仿你的数据分布。

最常用的是监督微调（SFT）：

```text
输入（instruction）：把句子翻译成英文
期望输出（output）：The weather is nice today.
```

训练时，模型生成答案，程序计算“模型输出和期望输出的差距”，通过反向传播更新参数，让差距越来越小。

## 3. 数据：微调的核心

数据格式（JSONL，一行一条）：

```json
{"instruction": "把句子翻译成英文", "input": "今天天气很好", "output": "The weather is nice today."}
{"instruction": "总结下面这段文字", "input": "……", "output": "……"}
```

数据质量规则：

- **宁可少而精，不要多而脏**：几百条高质量数据常好过几万条噪声；
- **格式必须统一**：模型学到的是“模式”，模式乱则输出乱；
- **训练集和测试集要分开**：测试集必须是模型没见过的；
- **不要让模型背答案**：如果输入几乎不含信息、输出却很长，模型会“背数据”而不是“学能力”。

## 4. LoRA：让微调变得便宜

全量微调要更新几十亿参数，普通电脑跑不动。LoRA（低秩适配）的做法：

1. 冻结原始模型权重（不更新）；
2. 在部分线性层旁插入两个很小的矩阵 A、B；
3. 只训练 A、B（通常占全部参数的 0.1%～1%）；
4. 推理时把 A×B 加回原权重，等于得到一个“微调版”模型。

QLoRA 再进一步：把原模型量化成 4-bit 加载，显存需求大幅下降。**如今绝大多数个人微调项目都是 LoRA/QLoRA。**

## 5. 微调的标准流程

1. **定义目标**：明确要让模型学会什么行为；
2. **准备数据**：收集、清洗、格式化为 JSONL，切分训练/验证/测试；
3. **选基座模型**：中文场景常用 Qwen 系列；数据量少选小模型（0.5B～7B）先试；
4. **训练**：用 LoRA 跑几个 epoch，观察训练/验证损失；
5. **评估**：在测试集上人工抽检 + 跑固定评测题，对比微调前后；
6. **部署**：合并 LoRA 权重，导出 GGUF（Ollama 可用）或直接加载。

## 6. 两条实操路径（本项目提供脚本）

### 路径 A：本机 Apple Silicon（MLX）

用 `examples/finetune/finetune_lora_mlx.py`。MLX 是苹果的机器学习框架，在 M 系列芯片上效率高，适合 0.5B～4B 小模型。

### 路径 B：免费 Colab（Unsloth）

用 `examples/finetune/unsloth_colab.py`。Unsloth 训练速度快、显存省，免费 T4 就能微调 1.5B～7B 模型，适合没有 Mac 或想要更强模型的情况。

## 7. 评估与常见坑

评估：

- 损失下降 ≠ 效果好，必须看测试集上的实际输出；
- 准备一组固定问题，微调前后各跑一遍，人工对比；
- 警惕“灾难性遗忘”：微调后模型可能忘了原来的通用能力，需要抽样验证。

常见坑：

- 数据里有重复或错误答案，模型学歪；
- 训练轮数过多导致过拟合（只会背训练数据）；
- LoRA 秩（rank）太小，学不动新行为；
- 微调后直接部署，没对比“改提示词是否已经够用”。

## 8. 动手练习

1. 先阅读 `examples/finetune/finetune_lora_mlx.py`，找到“数据集”和“训练参数”两处；
2. 按 `examples/finetune/README.md` 跑通一次最小实验（建议用 0.5B 模型）；
3. 准备 20 条你自己的“输入 → 输出”数据，观察模型是否学会格式；
4. 用 `ollama` 的 `Modelfile` 把微调后的 GGUF 加载成本机模型，体验完整闭环。

## 9. 本项目的真实实验记录（2026-08-28）

在 M1 Pro（16GB 内存）上用 0.5B 模型 + 5 条训练数据跑了 30 步 LoRA：

- 可训练参数只有 0.297%（LoRA 特征）；
- 训练损失从 1.23 降到 0.13，显存峰值 1.23 GB；
- 微调前问“用一句话介绍小米”，模型回答内容正确但格式随意；
- 微调后同样的问题，模型严格按训练格式输出，但内容借用了最相似的训练样本（华为）；
- 验证集样本（比亚迪，训练时没见过）格式正确，内容则是“动力电池（宁德时代）+ 智能终端（华为）”的混合。

这个结果完美演示了两个要点：

1. **微调学的是行为/格式**——格式一次就学会了；
2. **少量数据会让模型“背最像的样本”**——所以数据质量和数量直接决定效果，纯知识类需求应优先用 RAG。
