# 第 3 天课程：综合项目 + 动手改造 + 收尾（含答案）

> 配套阅读：`docs/05-综合项目.md`、`docs/07-动手改造指南.md`、`docs/08-完成度审计.md`。

## 一、把三样技能组合成一个系统

生产中的典型组合方式是：**把 RAG 变成 Agent 的一个工具**。

`examples/assistant/assistant.py` 就是这么做的：`search_knowledge()` 内部就是 RAG 检索；模型面对问题自己判断——知识问题调检索、计算问题调计算器、组合问题连续调多个工具。

分工再强调一次：

| 技能 | 解决什么 | 类比 |
|---|---|---|
| RAG | 模型不知道的资料 | 发参考资料 |
| Agent | 模型做不到的动作 | 配计算器/数据库 |
| 微调 | 模型不听话的格式 | 岗位培训 |

## 二、微调模型接入综合项目（实测结论）

把只微调过“公司介绍”的 0.5B 模型接入综合示例，结果：8 轮循环里只会重复训练过的句子，不调用工具。

结论：**微调会窄化模型行为**。想让微调模型当 Agent，训练数据里必须包含工具调用格式样本；通用 Agent 任务用通用强模型（本项目用 qwen3.5:4b）。

## 三、动手改造（今天的主线任务）

按 `docs/07-动手改造指南.md` 的 5 步，给综合示例加一个自己的工具（或往知识库加一篇自己的文档）：

1. 写工具函数（返回字符串）；
2. 注册进 `TOOLS` 和 `TOOL_DESC`；
3. （可选）加演示问题；
4. 在 `evaluate_agent.py` 加评估用例；
5. 跑验收：

```bash
python3 examples/agent/evaluate_agent.py
python3 examples/practice/verify_all.py
```

范例：汇率工具 `get_exchange_rate`（评估 6/6 通过），代码和步骤都写在指南里。

## 四、收尾

1. 闭卷重做自测，目标 ≥16/20：

```bash
python3 examples/practice/quiz.py
```

2. 用进度跟踪器勾选完成项：

```bash
python3 examples/practice/track_progress.py
```

3. 把“自测分数 + 改造内容 + verify_all 输出”记录下来，作为最终完成证据。

## 五、检查点答案（先自己答再看）

1. 综合示例把 RAG 放在了哪一层？
   **答：作为 Agent 的一个工具（search_knowledge）**，模型按需调用。
2. 微调在组合系统里的角色是什么？
   **答：行为/格式层**（让模型更稳定地输出指定格式），不参与运行时的检索和工具调用。
3. 改完工具后，必须做哪一步才能确认没改坏系统？
   **答：跑评估（evaluate_agent.py）和一键验收（verify_all.py）**。
